Action Book 5 · The money

Two directions, and they must never be added together. 12 actions — 5 the brand, 3 the creator, 4 admin, plus the three watching actions that run through every phase. Five of them do not exist, and none of this has ever run.

NEW · CHANGE · KEEP · BOTH both phones shown · MONEY IN he puts it in to pay creators · MONEY BACK a sale returns it · ADMIN
Read this before anything else in this book. Every table underneath these screens is at zero rows in production — escrow_entries, wallet_transactions, influencer_withdrawals, brand_withdrawals. Every wallet reads ₹0. The money system has never once run. Everything in this book is either a screen that does not exist, or machinery that exists and has never executed. That is not a criticism — nothing has completed end to end yet — but it means the first real campaign to finish will be the first test of all of it at once.

Why SC-33 exists at all
A shopper returns something. Her number goes down. Without a screen explaining it, she concludes she has been charged. SC-33 says the opposite in plain words: it was still inside the 7 days, so it had never reached your wallet — your balance has not gone down, this sale simply never completed.

Showing one number. The single most damaging thing this screen could do.

The four schema decisions the books forced
  1. A negotiation must belong to a set row, not a floating agreement. Book 1. The largest single piece of backend work, and four actions wait on it.
  2. A counter must carry which kind it is — money or structural. Book 1. Same shape in the data, opposite consequences.
  3. creator_posts needs campaign_influencer_id. Book 4. Five features blocked, including AD-03 which cannot be built without it.
  4. Live links must be a row per channel, not a column. Book 4. One post_url makes the founder's per-channel rule unbuildable.
The three things that must be repaired before a money screen is built
The 16 production sales are practice rows with no fee and no brand share computed. Repair or exclude them.

cancelInfluencer writes an invalid contract status. Confirmed live, will throw. Carried through all five books unfixed.

Nothing forces a brand to confirm she went live. Tranche 2 sits behind a button with no deadline. An automatic release belongs on SA-04 and has not been designed.
What is left
The screens are drawn, addressed, indexed and written up. What has not happened: the founder has not locked the mockups, and there is no implementation plan yet — one ordered migration list collecting every schema change these five books ask for. That is the next artefact, and it should not be written until the mockups are locked.
