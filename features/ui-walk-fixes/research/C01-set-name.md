# C01-set-name — Set name pre-filled "SET A"

## TODAY
Brand app, New set screen (reached two ways: "Next: add a set" after naming a new campaign, and "+ Add another set" on a campaign page). Top to bottom: back arrow + title "New set"; the campaign name in small grey capitals; label "Set name *"; a text box that is ALREADY FILLED with black text "Set A" (or "Set B"/"Set C" - the letter is simply the number of sets the campaign already has); under the box on the right a counter "5 / 60"; hint "Creators see this name in their invitation."; then Aim (three cards), Mode of work (two chips), Branch (Store Visit only), Posting date, and a black "Save set" bar at the bottom. The box has no grey hint text at all - if she wipes "Set A" the box is completely blank. To use her own name she must tap in and backspace "Set A" first (nothing is auto-selected, there is no clear button). If she leaves it, the set is saved as "Set A". If she clears it and taps Save she gets the red line "Enter a set name." A third way in - "Create set" from the creator pool - opens the same screen with the name box completely EMPTY and no hint text either.

## ROOT CAUSE
The suggestion is passed as a route param and used as the INITIAL VALUE of the text box, not as a placeholder.
1) C:\WORK\inflx-platform\Packages\Mobile\src\screens\brand\BrandSetEditScreen.js:44 - `const [name, setName] = useState(existing ? existing.name : (suggestedName || ''));` seeds the field's value with the suggestion.
2) Same file :135 - the `<TextField4 ... value={name} ... />` for the set name passes NO `placeholder` prop, so there is no hint text in any state (TextField4 already supports `placeholder`, bits4.js:46-55; the campaign-name field on the previous screen uses it).
3) The suggestion is produced on the phone: BrandCampaignNewScreen.js:48 always sends `suggestedName: C4.set.suggestedName('A')`; BrandCampaignDetailScreen.js:48-49 computes the letter from the set COUNT (`String.fromCharCode(65 + Math.min(25, c.setCount))`) and sends `Set <letter>`; copy4.js:83 is the template `Set ${letter}`. There is no placeholder string for the set name in copy4.js at all.
4) The server does NOT name sets. Name is required on create and on edit: backend/src/services/campaignState.service.js:250-253 returns "Enter a set name." for a blank or >60-char name, and campaign.controller.js:708-709 turns that into a 422; :770 does `name.trim()` straight into the INSERT. A server helper `nextSetLetterName` exists (campaignState.service.js:294-302) but is dead code - exported and unit-tested only, never called by any controller.
So this was built to the item 4 prompt as written ("Set name: required, suggested as 'Set A', 'Set B' by order in the campaign", features/item4-campaigns-sets/PROMPT.md:219 and :370) - the word "suggested" was implemented as "pre-filled". It is a design decision the founder now wants changed, not a coding accident.
