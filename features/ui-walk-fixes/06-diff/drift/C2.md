## "What came back?" — the note box that kept nothing (REMOVED in the final review, 2 Oct 2026)

**Before (live since item 11, and through the three waves of this build):** `ConfirmReturnSheet11`
drew a note box under an item marked Missing or Damaged, and what was typed in it disappeared
letter by letter — the pop-up handed the box no value and a do-nothing handler. The server was
checked (read only): `POST …/return/confirm` → `remoteReturn.service.js` `confirmReturn` reads
`body.answers` as `[{ lineId, status }]`, writes `return_status` and nothing else — it has no note
field and no column for one on this step. The first passes of this slice left the box as it was
("not fixed, by rule") and pinned only that what is sent is `{ lineId, status }`.

**Now:** the box is not drawn in the brand's pop-up. Marking an item Missing or Damaged selects
that answer and nothing else appears. This is what item 11's own locked frame R13 draws (three
buttons per item, no note), so it restores a locked board rather than deciding something new; and
this build's keypad work had brought the dead box squarely into view above the keypad, where it
would have been met at the walk. **A visible change — one line for the walk:** "the note box that
used to appear under Missing / Damaged on 'What came back?' is gone; it never kept what was
typed."

- How: `components/remote/bits11.js` `ThreeWayCheck11` gained an opt-out prop, `withNote`
  (default `true`); `sheets11.js` passes `withNote={false}` and no longer passes the do-nothing
  `onNote`. The creator's own check on her Remote shoot (R9, `RemoteShootScreen`) passes nothing
  and is unchanged: her note shows what she types and is sent with her check. No server change,
  no testID removed from any screen that kept the box (`confirm-check-{id}-note` no longer exists
  on this pop-up only; no Maestro flow or `qa/` script used it).
- **Not built, and it would be a founder decision:** letting the brand's note be SAVED. That is
  new behaviour and needs the server to accept and store a note per item (a new column). The
  founder was asked in research C03 ("Fix it in this same piece of work?") and has not answered
  that part; removing the dead box does not close the question, it only stops the box eating
  typing in the meantime.

## Review round — three findings, all three real, all three fixed

**1 · A pinned button that refuses a box out of sight** (`sheets4.js`, `sheets6.js`, new
`useSheetReveal` in `settings/sheets.js`). With the button pinned above the keypad the body can be
134 points tall; "Create" with no date, "Send counter" with the fee emptied, or a description the
server would not save drew its red line under a box that had scrolled away, and the tap seemed to
do nothing. Chosen fix: the red line STAYS under its own box (U10 — nothing is moved, and nothing
is said twice when the whole pop-up is on show) and the body scrolls to the first refused box, top
to bottom. A box that fits is shown whole and moved as little as possible; one taller than the
body is shown from its bottom edge, where the red line is. With the keypad closed nothing moves.
  - Duplicate a set: name, then date; also after a refusal from the server.
  - The brand's Counter back: commission, fee, the deliverables chooser, the re-use places, the note.
  - Rename / Edit description (`TextSheet4`): the one field.
  - **Adjacent fix, same sheet:** a refusal from the server that names a box Duplicate does not
    have (anything but `name` / `go_live_date`) was filed under that name and drawn NOWHERE. It is
    now said in the footer, on the line the sheet always had there (`errs.form`).
  - Not given the same treatment, and why: the note boxes of Decline a counter, Reject a pitch,
    the note on a file and both reports can only be refused for length, and the box itself stops
    typing at that length; "Ask for changes" and "New group" have one box each, and the body's
    own helper (finding 3) keeps 64 under that box in view, which is where their red line appears.
  - New testIDs (none removed): `duplicate-name-field`, `duplicate-date-field`,
    `${testID}-field` on the text sheet, `brand-commission-field`, `brand-fee-field`,
    `brand-deliverables-field`, `brand-usage-field`, `brand-counter-note-field`.

**2 · The state → city picker's chosen cities** (`StateCityPicker.js`). The chips were a plain
block that could neither scroll nor shrink; two rows of them on a short phone with the keypad open
left the results less than one row, and "Select all" on a 33-city state left the list nothing.
They are now in a scroller of their own (`city-chips`), beside the list and never around it. With
room to spare it is exactly as tall as its chips — the picker at rest looks as it did, for any
number of cities that fits. When the room runs out the chips give way first (four times as readily
as the list), down to one chip, and scroll. Not the reviewer's "cap at two rows": a cap changes
the picker at rest for anyone with three rows of cities, and giving way first does the same job
only when it is needed. Two small things came with it: the chips on the second step now carry the
same "Remove {city}" label the first step's had, and each chip has a testID (`city-chip-{id}`).

**3 · The counter under the box being typed in** (`settings/sheets.js`, frame C6). Android brings
a focused box up only until its own bottom edge touches the bottom of the body, so "44 / 200"
sat just under the pinned footer. The body of every scrolling `fit` sheet now finishes that scroll
with the helper the screens' forms use (`useRevealFocusedInput`, imported from
`components/shell/FormScroll.js` — that file is not edited): 64 under the box, the box's own top
never leaving the top edge, never backwards. New optional Sheet prop `revealBelow` (0 = leave it
to Android). It only scrolls: the sheet's shape and layout do not depend on the keypad. It also
reaches board G's `MoveTimeSheet10`, the only other scrolling `fit` sheet in the app; list-shaped
and old-shape sheets are untouched. Read from the code, like the finding itself — the walk decides
whether 64 is the right number on a real phone.
