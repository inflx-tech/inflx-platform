The city filter itself was never broken. The SQL lowercases both sides and, run against the production database, returns Vijayawada 6, Nellore 16, Hyderabad 3. What broke was that doSearch had no stale-response guard: each keystroke fires a debounced request, the backend cold-starts (8.2s measured), and a slow earlier response could land last and repaint the unfiltered list — so the filter looked inert.

Worth knowing: 37 of 73 creators have no city on record, so any city filter drops roughly half the roster by construction. That is data coverage, not a bug — but it makes city filtering feel far more aggressive than expected.
