# Workflow Prediction — Scoped proposals (Phase 8)

Predicted behaviour the mockups demonstrate (confirmed in 06-diff; 8b mobile via Maestro, batched).

## Creator store-browse + scoped pitch (`scoped-proposal.html`, influencer app)
1. Discover → a brand (accepting proposals) → **Browse products** (grid + search).
2. Pick a **scope**: whole store · a category · these products.
3. Select products (for product scope) + pick a **theme** (Street Style…).
4. Add the pitch (title/message/deliverables — existing) → **Send proposal**.
5. Existing guardrails apply (cooldown, limits, TTL).

## Brand inbox (`brand-proposal-scoped.html`, brand app/web)
1. The incoming proposal now shows its **scope + theme + the proposed products** on its face.
2. Accept / counter / reject (existing).
3. On accept → a Street Style experience **draft** is seeded for the creator with those products.

## Creator Studio (payoff)
- After accept, the creator's Studio shows a **draft experience** (theme + products already set, `source_proposal_id`) — they add a featured image and publish.

## What this proves
The creator-initiated path now feeds the experience engine end-to-end: browse → scoped+themed pitch → accept → seeded draft → publish → renders on the follower home. The full two-way Creator Commerce loop.
