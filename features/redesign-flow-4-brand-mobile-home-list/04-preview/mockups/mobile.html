Backend-source audit · Flow 4 · Brand mobile

BrandHomeScreen — APIs

  • brandApi.getMe() → returns brand profile (status, business_name, wallet_balance, rejection_reason)
  • brandApi.getCampaigns() → returns campaigns array
  • brandApi.getInboxSummary() → returns inbox.* counts

Home tiles

  • Wallet amount · brand.wallet_balance
  • Active campaigns · campaigns.filter(active|live).length
  • Total campaigns · campaigns.length
  • Action Required count · sum(inbox.pending_*)
  • Pending-wallet alert · campaigns.filter(s=pending_wallet).length
  • Status banner · brand.user_status / status (pending/rejected/suspended)

Home · Campaign cards (top 5)

  • Card · c.name
  • Card · c.status badge
  • Card · c.total_budget (rendered only if > 0)

Quick Actions

  • 6 tiles linking to: Campaigns · Wallet · Negotiations · Enquiries · Conversions · Influencers
  • "View My Store" tile dropped vs current (less-used; brand store browsable from the web)

List screen — APIs

  • brandApi.getCampaigns() · same endpoint as home
  • brandApi.cancelCampaign(id) · per item in bulk
  • brandApi.deleteCampaign(id) · per item in bulk

List · per-card fields (ALL backed)

  • c.name · campaigns.name col
  • c.status · campaigns.status col
  • c.start_date · campaigns.start_date col
  • c.total_budget · campaigns.total_budget col
  • c.created_at · used for sort (campaigns col)
Dropped from list cards (same phantom as web Flow 3):
Today's mobile card renders "👥 N influencers" when c.sets[*].influencers.length > 0. Verified-twice: GET /campaigns SELECT * never returns nested sets; influencerCount always 0; row guarded so it never appears — but the dead code is misleading and increases maintenance surface. Mockup ships the list without the influencer-count attempt. CSV / web Flow 3 retain the same phantom flag — open carve recorded.

Status filter chip set: mobile keeps the existing compact 5-chip set (All · Active · Draft · Needs funding · Completed) rather than the web's 8-chip set, because the horizontal scroll row is mobile-native and the 5 cover the most-used statuses. active+live combined under "Active" (current behaviour).
Functional preservation: all API calls unchanged · selection state machine unchanged · bulk cancel/delete confirmation Alerts unchanged · filter + sort logic unchanged · navigation routes unchanged · all hrefs/navigation targets preserved · openWebDashboard deeplink behaviour unchanged. Zero functional / backend / logic / DB impact — visual + UX only.
