3 · What it consolidates

✕Three screens products/page.js + products/listing/page.js + ListingTemplateLayout.js → one listing shell; browse implemented once, not three times.
✕Three CSS systems (.prd + .lst inline + Tailwind) → one token set (the Instagram-clean system).
✕Three tab vocabularies (Products/Offers · Inventory/Add/Offers · Fleet/Add/Upload) → one: Inventory · Add · Offers.
◐Per-vertical ternaries + emoji spec strings → one card with a small vertical chip; vertical-specific fields live in the Add wizard, not the grid.
＋Coverage fixed: fluid min(1400px,100%) container + auto-fill grid replaces maxWidth:960 / max-w-[780px] — no more narrow column with empty gutters.
＋Mobile gets real product management (Add/Edit), not a read-only "add on web" store.
Scope: frontend-only — web (Vercel) + mobile (OTA), over the existing listing/product endpoints. No backend, no DB. Consistent with the Campaign Command Center and the influencer app. That completes the four surfaces we mapped: influencer app, brand campaign command center, brand listing — all one Instagram-clean system.
