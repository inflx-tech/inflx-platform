This control is mandatory, not a nice-to-have. The auto-complete cron keys off end_date < CURRENT_DATE, which never matches a NULL end date. Without an explicit End, an ongoing campaign would run forever.

What "End promotion" does

Sets end_date = today — every creator coupon stops working (the existing expiry check fires)
Campaign drops out of follower discovery immediately (existing end_date >= CURRENT_DATE filters)
Cron picks it up and moves status → completed once tranches settle
Commission already earned is unaffected — it settles on its own return-window schedule

Why not automatic on stock-out

✕
brand_products.stock exists but nothing decrements it on an order. Stock is a brand-entered attribute today, so "auto-end when stock closes" would be reading a number nobody updates. Ending is brand-declared until stock decrement is wired at checkout — a separate piece of work.

Offer dates live on the offer, not here

✓
The discount clock already has a home: brand_offers.store_starts_at / store_ends_at (migration 084), NULL = unbounded, enforced in the adapters. Dates get asked inside the offer builder, only when a discount is attached — and disappear from the campaign level entirely.
Also ships in Packages/Mobile brand campaign detail — ending a live campaign is a live-campaign capability, and only campaign creation and listing are web-only by design.
