🤝 Domain 3 — Acceptance / Negotiation / Contract

After a brand invites an influencer: accept, reject, or negotiate → contract → sign → active. All logic in offer.controller.js.

The 3 branches from an invited offer Influencer decides

invited offer
→ influencer picks one of:

✅ ACCEPT

POST /offers/:id/accept
  • Handpick → accepted + auto-create draft contract
  • Open-group → applied (NO contract; brand must approve-application)
  • agreed_fee = COALESCE(fee, budget)

❌ REJECT / DECLINE

POST /offers/:id/decline
  • reason required: not_relevant / fee_too_low / schedule_conflict / already_partnered / other
  • → declined
  • Open-group UI labels it "Pass"

💬 NEGOTIATE

POST /offers/:id/negotiate
  • Only if allow_negotiation≠false AND not open_group
  • proposed_fee or proposed_commission_pct
  • → CI negotiating, opens turn-based thread

Negotiation thread (turn-based) BI

walkaway → declined
POST /negotiations/:id/respond — actions: counter / accept / walkaway
  • WRONG_TURN enforced — only the current_turn party may act
  • counter → flip turn, reset 48h SLA · accept → negotiations=agreed, CI=accepted (last-turn fee/commission), auto-create contract · walkaway → CI=declined
  • SLA cron (30min): stalled 48h → walked_away + both notified
⚠️ Drift: "max 2 negotiation rounds" does NOT exist — counters are uncapped. The "2" is the deliverable revision_limit (post-contract content revisions), a different mechanism.

Contract chain (after accept) — note the brand-APPROVE gate the spec omitted

draft
→B approve
pending_influencer
→I sign
pending_brand
→B brand-sign
active

① Brand approve

POST /contracts/:id/approve
  • sets clauses/bonus/content_requirements/production_mode
  • wallet pre-check (base+bonus)×1.08
  • draft → pending_influencer

② Influencer sign

POST /contracts/:id/sign
  • typed_name required
  • pending_influencer → pending_brand

③ Brand counter-sign

POST /contracts/:id/brand-sign
  • wallet lock = fee×(1+8%) else WALLET_INSUFFICIENT
  • → active, CI=contracted, 3 escrow tranches, release T1, auto-create deliverables
⚠️ Spec gap: contract is born draft, not pending_influencer. The brand-approve step gates everything — influencer can't sign until the brand approves.

The REAL "max 2": revision_limit=2 → REVISION_LIMIT_EXCEEDED on the 3rd revision request. confirm-live sets CI=active; when ALL deliverables live → release T2 (25%).
