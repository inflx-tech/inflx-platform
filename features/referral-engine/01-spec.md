# referral-engine — Contract 1: referral attribution + accrual spine (backend)

> **Contract 1 of 4** in the Referral / Strategic-Partner-Agency feature.
> The backend foundation: the referral-edge data model, the accrual engine,
> and the three confirmed-revenue hooks. Contracts 2 (admin controls),
> 3 (agency mobile role) and 4 (influencer Refer & Earn) build on this.
> Backend-only — no UI in this contract.

## Problem / goal
INFLX wants a marketing referral channel: a referrer (a partner **agency** or
an **influencer**) earns an admin-set % of the **platform's own revenue**
generated by an entity they referred (a **brand** or an **influencer**), for
**12 months** from the referral. This contract builds the spine that records
referrals and accrues that commission correctly — carved from the platform's
slice only, never reducing influencer earnings or brand net, and only on
**confirmed** revenue so refunds/reversals never over-pay.

Locked model (founder, 2026-05-31):
- **Brand referred** → referrer earns % of that brand's **subscription** +
  **protection fee** (campaign escrow fee). NOT commission.
- **Influencer referred** → referrer earns % of the **public-purchase
  commission** the platform makes from that influencer's links. ONLY.
- One admin-set `pct` per edge (default global, per-edge overridable later in
  Contract 2). Flat **12-month** window. No caps, no ceilings, no operators.
- One active referrer per referred entity (first-touch, locked). No self /
  circular referral.

## Data / contracts

### New tables (migration `078_referral_engine.sql`, additive, idempotent)
**`referral_codes`** — a referrer's shareable code.
- `id uuid pk`, `referrer_type text check in ('agency','influencer')`,
  `referrer_id uuid not null`, `code text unique not null`,
  `created_at timestamptz default now()`.
- Unique `(referrer_type, referrer_id)` — one code per referrer.

**`referral_edges`** — the locked referral relationship.
- `id uuid pk`
- `referrer_type text check in ('agency','influencer')`, `referrer_id uuid`
- `referred_type text check in ('brand','influencer')`, `referred_id uuid`
- `pct numeric(5,2) not null` (e.g. 25.00)
- `kind text not null default 'referral' check in ('referral','managed')`
- `status text not null default 'active' check in ('active','expired','ended')`
- `source text not null check in ('signup','admin')` (admin/code origin)
- `code_id uuid null references referral_codes(id)`
- `created_by_admin_id uuid null`
- `started_at timestamptz not null default now()`
- `expires_at timestamptz not null` (= started_at + interval '12 months')
- `ended_at timestamptz null`, `created_at`, `updated_at`
- **`create unique index uniq_referral_active_referred on referral_edges
  (referred_type, referred_id) where status = 'active'`** ← the dedup guarantee.

**`referral_ledger`** — one row per accrued revenue event (source of truth).
- `id uuid pk`, `edge_id uuid not null references referral_edges(id)`
- `referrer_type text`, `referrer_id uuid` (denormalized for fast reporting)
- `source text check in ('subscription','protection_fee','commission')`
- `source_ref_id uuid not null` (subscription_invoices.id / escrow_entries.id /
  follower_transactions.id)
- `base_amount numeric(12,2)` (the platform's slice for this event)
- `pct numeric(5,2)`, `amount numeric(12,2)` (= base × pct/100)
- `payout_status text not null default 'pending' check in ('pending','paid')`
- `paid_at timestamptz null`, `created_at timestamptz default now()`
- **`unique (source, source_ref_id)`** ← idempotency: a webhook retry or cron
  re-run cannot double-accrue.

**`influencers.referral_earned_total numeric(12,2) default 0`** — reporting
counter; referral payouts land in existing `wallet_balance` and are itemized in
`referral_ledger` (the "separate referral line").

### Accrual hooks (wired at verified existing points)
| Source | Hook (file:line) | base_amount | referred entity |
|---|---|---|---|
| subscription | `webhook.controller.js:237` `handleSubscriptionCharged` (after invoice `status='paid'`) | invoice `amount_inr` | the brand |
| protection_fee | `escrow.service.js:102` `processTrancheRelease` (per tranche) | that tranche's `escrow_fee_amount` | the campaign's brand |
| commission | `commission-confirm.job.js:39` (pending→wallet, post 30-day window) | the txn `marketplace_fee_amount` (the platform's commission slice; was `platform_fee` pre-M059) | the link's influencer |

Each hook calls `referral.service.accrue(...)` inside the **same DB transaction**
as the underlying money movement, wrapped so an accrual failure logs + no-ops
**without** breaking the host payment/cron (referral is additive, never blocks
core money). The service: resolves the active edge for the referred entity,
checks `now() <= expires_at` and `status='active'`, writes the ledger row
(idempotent), and — for `referrer_type='influencer'` — credits the referrer's
`wallet_balance` + `referral_earned_total` and marks the ledger `paid`. For
`referrer_type='agency'` the ledger row stays `pending` (agency wallet arrives
in Contract 3; no agency referrers can exist before then).

### New API endpoints
None in this contract (engine is internal). Admin/agency/influencer endpoints
arrive in Contracts 2–4.

### Money / units / attribution
- All rupees `numeric(x,2)` per platform convention.
- Referral amount is carved from the platform's slice only — the existing
  influencer commission credit, escrow `net_to_influencer`, brand_net, and
  subscription amounts are **unchanged**.

## Non-functional
- **Auth/role gates:** n/a (server-internal). Edge creation in this contract is
  test-seeded/admin-only; the signup-code path is Contract 3.
- **Failure modes handled:**
  - Duplicate revenue event (retry / re-run) → `unique(source, source_ref_id)`
    makes accrual idempotent (insert-or-ignore).
  - No active edge / expired window → silent no-op, host path proceeds.
  - Attempt to create a second active edge for an entity → blocked by partial
    unique index (dedup).
  - Self-referral / circular (A→B while B→A active) → rejected by guard.
  - Accrual error → caught + logged; underlying subscription/tranche/commission
    confirmation must still succeed (referral never breaks core money).
