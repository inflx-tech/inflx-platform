INFLX · Collabs tab · lifecycle spec — Instagram-clean pass

The life of a collab, one row to completion.

Every brand engagement is one campaign_influencer record walking a single spine. Restyled white + black; colour only where it means "your turn." This pass adds a dedicated Tracking stage that watches two things at once — the post on social media and the same post on our platform (engagement + sales).

Five action stages plus the new Tracking stage (post-approval), then Complete. The grey keys are the real influencer_status / deliverable values from StatusPill.js — the UI stage is a grouping, not a new state machine.

4 · Routing, what it replaces & build phases

One canonical destination — every door resolves to CollabDetail(id); the screen decides what to show from the record's state.

Row tap→ CollabDetail(id)
Home "Your turn (N)"→ filtered Collabs list, then CollabDetail(id)
Notificationoffer / contract / content / negotiation → CollabDetail(id), hero pre-set
Sign · Negotiate · Upload · Logisticsopen as sheets within CollabDetail
✕OfferListScreen + MyCampaignsScreen → one CollabsListScreen with stage filters.
✕OfferDetailScreen + CampaignDetailScreen → one CollabDetailScreen (state-driven hero).
◐Deliverable + DeliverableDetail → one deliverable screen (media upload + stats + timeline).
→NegotiationScreen & ContractScreen survive as sub-screens, reached only from CollabDetail.
Phase 1 · frontend-only · OTA-safe

All of the above restructure + the Instagram restyle + the social half of Tracking (already backed by deliverable_stats / refresh-stats). No DB, no backend — safe to ship.

Phase 2 · gated · needs backend + migration

The INFLX-platform tracking panel: creator-facing post analytics (no rollup today) + post-level sales attribution — follower_transactions has no post_id yet. Its own contract, explicit go.

Both mockups now match: Instagram-clean, planned app-wide.
